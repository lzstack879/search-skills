# 提示词 · 种子表生成（gen_seeds）

> 用途：让模型凭行业知识列出一批**真实存在的中型公司**，作为深挖的起点。
> 调用方注入 ICP 字段：{{PRODUCT}} {{INDUSTRIES}} {{GEOGRAPHY}} {{SIZE}} {{TITLES}} {{SIGNALS}} {{MAX_EMPLOYEES}} {{COUNT}}

## 角色

你在为下面这家公司列潜在客户清单：

| 项 | 值 |
| --- | --- |
| 我们卖什么 | {{PRODUCT}} |
| 目标行业 | {{INDUSTRIES}} |
| 目标地区 | {{GEOGRAPHY}} |
| 目标规模 | {{SIZE}} |
| 买家角色 | {{TITLES}} |

你要找的是**买方**——需要这套东西的公司；不是**卖方**——做同样东西的同行。

## 第 0 步：从产品反推「需求信号」

在列公司之前，先想清楚：什么样的公司特征意味着它**现在需要这个产品**。
把信号写成**可观察的组织特征**（部门构成、文档量、合规要求、扩张动作），
不要写成行业刻板印象（“制造业都需要数字化”这种没用）。

已经给出的需求信号：

{{SIGNALS}}

如果没有给出，你就根据 `我们卖什么` 自己反推 3~5 条，并在输出里用它们。

## 第 1 步：用信号筛公司

对每家候选公司，必须能说清它命中**第 0 步的哪一条信号**（填进 `need_signal`）。
命不中的不要列。

## 第 2 步：排除不该列的

| 不要 | 要 |
| --- | --- |
| 卖同类产品的同行 | 用这类产品的甲方 |
| 员工 > {{MAX_EMPLOYEES}} 的巨头 | 中型企业，见上面 `目标规模` |
| 上市集团总部 | 家族企业、区域型、细分领域第 3~10 名 |
| 模型只记得住的名牌 | 你确信存在、但不出名的公司 |

## 硬性规则

1. 只列**真实存在**的公司，域名必须是你确信存在的官方主域，**不要编造**。
2. 必须给出 `employees`（员工数估计，单位人）和 `listed`（是否上市）。
   估计超过 {{MAX_EMPLOYEES}} 或已上市的，**自己删掉，不要输出**。
3. `why_fit` 只能写类型化理由（组织特征、合规要求、业务形态），
   禁止编造具体事实（不要写“他们 2025 年买了 X”这种你无法确认的话）。
4. 同一域名只出现一次；已在排除列表里的公司不要重复。
5. 输出 `{{COUNT}}` 家，宁缺毋滥——凑不够就少给。

## 输出格式（严格 JSON）

```json
{
  "signals": ["第 0 步得到的需求信号，最多 5 条"],
  "companies": [
    {"name": "公司名", "domain": "acme.de", "country": "Germany",
     "industry": "细分行业", "employees": 300, "listed": false,
     "need_signal": "命中的那条信号", "why_fit": "为什么它现在需要这个产品"}
  ]
}
```
